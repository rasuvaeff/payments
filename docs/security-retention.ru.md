# Безопасность и хранение данных

Что гарантирует `rasuvaeff/payments`, чего он сознательно не делает и сколько
может жить каждый класс данных на вашей стороне. Читать вместе с
[security-retention.md](security-retention.md) (английское зеркало).

## Креденшалы

| Правило | Детали |
|---|---|
| Только в памяти | `StripeCredentials`, `PayPalCredentials` и OAuth-токены живут в immutable-объектах; ядро их никогда не сериализует |
| Заголовки, не URL | Аутентификация передаётся через `AuthContext` в заголовки запроса; никогда — в URI, query-string или лог |
| Нет общего auth-люка | `extra`-мешка для аутентификации нет; каждый адаптер владеет своим классом креденшалов |
| SensitiveParameter | Конструкторы креденшалов помечены `#[\SensitiveParameter]` — сам PHP маскирует их в stack trace |

## Карты и VO

PAN/CVC не попадают ни в один value object, вебхук-пейлоад, диагностическую
информацию или лог. `Money` — целые минорные единицы; в стеке нет поля, куда
могла бы поместиться сырая карта. Если ваше приложение работает с сырыми
картами — это вне этого стека и в вашем собственном PCI-scope.

Один креденшал сознательно другой: `client_secret` PaymentIntent в Stripe.
Stripe спроектировал его для браузера покупателя — `stripe.js`/Elements нужен
он для подтверждения платежа — так что передача на фронтенд *для этого одного
интента* и есть штатный поток, и адаптер `rasuvaeff/payments-stripe` выдаёт
его только через next action `ConfirmOnClient`, пока платёж ждёт покупателя.
Везде остальном он обращается как обычный креденшал: никаких логов,
персистенции дольше checkout-сессии, вебхук-пейлоадов или наблюдений.

## Валидация вебхуков

| Правило | Детали |
|---|---|
| Подпись обязательна в production | IP-allow-list не замена: Stripe — constant-time HMAC по точным сырым байтам, PayPal — сетевой verify-эндпоинт |
| Защита от replay | `WebhookEventStoreInterface::claim()` атомарен и вызывается только после валидации; дубликаты event id дают replay-исход и не запускают маппинг повторно |
| Клейм снимает только исключение | `release()` вызывается, когда обработка бросила исключение, — тогда ретрай провайдера сможет пройти. Любой исход, который вернулся значением, — включая терминальные `RejectedWebhookEvent` и `UnsupportedWebhookEvent`, — вызывает `complete()`: вердикт окончателен, и повторная обработка тех же байтов лишь повторила бы его |
| Завершённый клейм финален | `complete()` вызывается, как только событие надёжно принято. Без него хранилище не отличает клейм «в работе» от завершённого: процесс, убитый между клеймом и приёмом, оставит клейм, который либо истечёт (уже обработанное событие обработается повторно), либо не истечёт никогда (ретрай получит 204 replay, и событие потеряно молча) |
| Отозванный клейм не финализирует | `claim()` возвращает `WebhookClaimToken`, и оба финализатора требуют его обратно; при несовпадении — no-op. Воркер, чей лиз истёк и клейм перехвачен, не может ни `complete()` попытку нового владельца, ни `release()` его живой клейм — последнее открыло бы третью параллельную доставку |
| Неотображаемый payload терминален | `MalformedResponseException` от маппера становится `RejectedWebhookEvent`: те же байты — тот же вердикт вечно, а шторм ретраев приводит к отключению эндпоинта провайдером, из-за чего теряются последующие, здоровые события |
| Подпись покрывает полученные байты | Верификация использует тело ровно в том виде, в каком оно пришло, без round-trip декодирования: PHP экранирует не-ASCII, превращает `{}` в `[]` и теряет хвостовой ноль — пересериализованный документ уже не тот, который подписан, и не тот, с которым работает маппер |
| Тело должно дойти целым | Монтируйте маршрут до body-parsing middleware; уже прочитанный поток читается как пустой и сообщается исходом `empty_body` |
| Обязателен event id провайдера | Валидная подпись без провайдерского event id отвергается — такое событие не дедуплицировать |

## Креденшалы в дампах и отчётах об ошибках

| Правило | Детали |
|---|---|
| `#[\SensitiveParameter]` недостаточно | Он редактирует только stack trace. Носители секретов дополнительно определяют `__debugInfo()`, возвращающий `[REDACTED]`, и запрещают `__serialize()`/`__unserialize()` — дамп или запись в кэш не унесут значение |
| Цепочка исключений может нести запрос | `Psr18Transport` кладёт исключение PSR-18 в `previous`, а часть клиентов держат на нём упавший запрос — вместе с заголовком `Authorization`. Настройте репортер ошибок не прикреплять объекты запроса и вычищать `Authorization` перед отправкой |
| Провайдерский текст ограничен | Сообщения об ошибке от провайдера обрезаются до 1024 байт, прежде чем поедут дальше внутри исключения; срез откатывается до границы символа, чтобы лог-запись осталась сериализуемой |

## Что пересекает надёжную границу

`ObservedPaymentEvent` — единственное значение, которое можно ставить в
очередь и реконсиляцию:

- только скалярные поля из allow-list (`array<string, scalar|null>`);
- без сырых байт тела, заголовков валидации и `client_secret`;
- один провайдер во всех ссылках; ссылка на возврат обязательна для состояний
  возврата и запрещена для состояний платежа.

Сырые тела вебхуков могут храниться только короткое настраиваемое
аудит-окно и обязаны быть отредактированы (заголовки Authorization, секреты
подписей, данные карт) до записи. Причины отказа в валидации никогда не
попадают в ответы контроллера — `WebhookController` отвечает кодом статуса и
заголовком `X-Payments-Webhook-Outcome`, и ничем больше.

## Хранение по классам данных

| Класс данных | Хранение | Примечания |
|---|---|---|
| Операционные метаданные событий (`OperationId`, ссылки, состояния, времена) | Документированный аудит-период | Двигают реконсиляцию и поддержку |
| Санитизированные пейлоады `ObservedPaymentEvent` | Тот же аудит-период | Только скаляры |
| Сырые тела вебхуков + заголовки валидации | Короткое окно (часы–дни), затем удаление | Редактировать до записи |
| Креденшалы, токены, секреты подписи | Никогда не хранятся | Только в памяти |
| PAN/CVC | Никогда не хранятся | Вне scope by design |

Принуждение к срокам живёт в вашем приложении (слой персистенции и будущий
DB-пакет); контракты здесь делают границу тестируемой — поведение
редактирования и allow-list покрыто мутационно-гейченными тестами.

## Исключения и диагностика

`PaymentException` и подклассы несут только санитизированные метаданные
провайдера: код, тип, параметр и скалярные `details`. `ProviderRequestInfo`
может нести request id провайдера, остаток rate-limit и retry-after — никогда
auth-заголовки или произвольные заголовки ответа. Битый ответ провайдера
падает как `MalformedResponseException` с приложенной ошибкой парсинга, а не с
эхом сырого тела.

## Валидация идентификаторов

| Поверхность | Проверка |
|---|---|
| Ключи провайдеров, валюты, имена заголовков | White-list-паттерны с якорем `\z` (замыкающий `\n` не проскочит) |
| Ссылки провайдера (`pi_*`, `re_*`, order/capture id) | Грамматика на уровне адаптера; ядро проверяет непустоту + максимум длины |
| Event id вебхуков | Непустой, `[A-Za-z0-9_-]+`, не длиннее 255 байт |
